# Market Bot — Что можно улучшить

Документ подготовлен по результатам изучения кодовой базы (`trader-bot`, ~15.6k строк, v0.3.0).
Пункты сгруппированы по приоритету. Для каждого указаны конкретные файлы/строки и предлагаемое действие.

---

## 🔴 Критично (корректность / деньги)

### 1. Расчёт количества в ордере конфликтует по смыслам
`main.rs:678`
```rust
let qty = (decision.position_size_pct * 100.0) as i32;
```
`position_size_pct` — это доля от баланса (0.0–1.0), но здесь она превращается прямо в «количество лотов». Размер позиции никак не зависит от баланса, цены инструмента и `lot_size`. В результате ордер на 15% депозита превратится в `15` штук вне зависимости от цены бумаги и размера счёта.

**Действие:** считать количество как `floor(balance * pct / (price * lot_size)) * lot_size`, учитывать `InstrumentInfo.lot_size` и `min_price_step`. Вынести в отдельную функцию с юнит-тестами.

### 2. Порог уверенности захардкожен и игнорирует конфиг
`main.rs:550`
```rust
if decision.action != agent::Action::Hold && decision.confidence >= 0.6 {
```
`0.6` вшит в код, хотя в `AiConfig.min_confidence` (`config/data.rs:115`) уже есть настраиваемое поле. Настройка пользователя не применяется.

**Действие:** брать порог из `AiConfig.min_confidence`.

### 3. Риск-менеджмент из конфига почти не задействован в основном пайплайне
`config/data.rs:190` (`RiskManagementConfig`: `max_open_positions`, `min_balance_reserve`, `max_loss_pct`) прокидывается в `DecisionContext.risk_config`, но в `run_ai_account` (`main.rs:402`) нет проверок лимита открытых позиций, резерва баланса и максимальной просадки перед `execute_via_broker`. `RiskAgent` (полноценная проверка) в бинарнике не вызывается (см. п. 7).

**Действие:** добавить hard-check рисков непосредственно перед размещением ордера, а не только внутри неиспользуемого `SupervisorAgent`.

## 🟠 Высокий приоритет (архитектура)

### 4. Большая часть библиотеки не подключена к бинарнику
`main.rs` использует напрямую `TradingAgent` + `run_grid_account`/`run_ai_account`. При этом не задействованы:
- `provider/prediction/` — `EnsemblePredictor` (взвешенный блендинг 4 провайдеров);
- `agent/multi_agent.rs` — комитет `Analyst → Risk → Supervisor` (описан в `AGENTS.md` как рантайм-пайплайн, но по факту не вызывается);
- `strategy/gates/` — скрининг-пайплайн;
- `scanner/`, `stream/`, `backtest/`, `optimizer/`, `storage/` (ClickHouse), `telemetry/`.

Это расхождение между документацией (`AGENTS.md`) и реальностью, плюс мёртвый код на 30–40% крейта.

**Действие:** либо подключить эти подсистемы в основной цикл (тогда `#![allow(dead_code)]` станет не нужен), либо явно пометить их как экспериментальные (feature-flag `experimental`) и синхронизировать `AGENTS.md`.

### 5. Крейтовые `#![allow]` маскируют реальные предупреждения
`lib.rs:1-6`, `main.rs:1-6`
```rust
#![allow(dead_code)]
#![allow(unused_imports)]
```
CI (`.github/workflows/ci.yml`) гоняет `clippy --all-targets --all-features -- -D warnings`, но эти `allow` глушат целые классы предупреждений на уровне крейта — проверка проходит «зелёной» при накопленном мусоре (39 `#[allow]` по проекту).

**Действие:** удалить крейтовые `allow`, точечно `#[allow(...)]` только там, где обосновано; неиспользуемые импорты/код вычистить.

### 6. Дублирование иерархий ошибок
Есть `error.rs` (`BotError`, `OrderError`, `StrategyError`, `NewsAnalysisError`) и отдельный `core/error.rs` (`CoreError`) с частично совпадающими вариантами (`Strategy`, `InvalidConfig`, `NotFound`). При этом трейты в `core/traits.rs` возвращают `anyhow::Result`, то есть типизированные ошибки почти нигде не используются по назначению.

**Действие:** выбрать одну стратегию — либо `thiserror`-типы на границах модулей, либо `anyhow` внутри + типизированные ошибки на публичном API. Убрать дубли.

### 7. `run_standard_account` — пустая обёртка-дубликат
`main.rs:566` полностью делегирует в `run_ai_account`. Разделения «AI / не-AI» по факту нет — все стратегии (кроме Grid) идут через один и тот же LLM-путь.

**Действие:** либо убрать обёртку, либо реализовать реально отличающийся не-LLM путь для `Interval/Momentum/MeanReversion`.

### 8. `Box::leak` в hot-path конвертеров enum → утечка памяти
`core/types.rs:186` (`BrokerKind::as_str`) и `core/types.rs:227` (`StrategyKind::as_str`):
```rust
BrokerKind::Other(s) => Box::leak(s.clone().into_boxed_str()),
```
Каждый вызов для варианта `Other`/`Custom` навсегда утекает строку. При частых вызовах (dashboard, логи) — постепенный рост памяти.

**Действие:** сменить сигнатуру на `fn as_str(&self) -> Cow<'_, str>` или возвращать `String`.

## 🟡 Средний приоритет (надёжность / эксплуатация)

### 9. Конфиг грузится по жёстко зашитому относительному пути
`config/data.rs:277`
```rust
pub fn load_default() -> Result<Self> {
    Self::load("trader-bot/config/account.json")
}
```
Бот запускается только из корня воркспейса. `AGENTS.md:123` при этом обещает флаг `--config`, но CLI-парсинга в `main.rs` нет вообще.

**Действие:** добавить разбор аргументов (`clap`) и/или переменную `CONFIG_PATH`, задать разумный дефолт относительно исполняемого файла.

### 10. `.unwrap()` на путях, которые могут падать в рантайме
82 вызова `.unwrap()` по крейту. Особенно чувствительны создания `TradingAgent` в `main.rs:283` и `main.rs:430` (`.unwrap()` при инициализации на каждый аккаунт) — падение уронит весь процесс при старте.

**Действие:** заменить на `?`/`context()` с внятным сообщением; для стартовых ошибок — graceful-лог и пропуск аккаунта, как уже сделано для брокеров (`main.rs:254`).

### 11. Два `Cargo.lock`
`./Cargo.lock` и `./trader-bot/Cargo.lock` одновременно. В воркспейсе lock должен быть один (в корне).

**Действие:** удалить `trader-bot/Cargo.lock`, добавить в `.gitignore` при необходимости.

### 12. Заглушка фундаментальных данных
`analysis/fundamental_data.rs` — `FundamentalDataService` возвращает застабленные данные (интеграции Tinkoff/Finviz/Bloomberg/MOEX не реализованы). При `fundamental_analysis: true` в конфиге решения принимаются по фиктивным метрикам.

**Действие:** либо реализовать реальный источник (MOEX ISS API доступен бесплатно), либо явно логировать «fundamental data is stubbed» и не давать этому влиять на решение.

### 13. Секреты в открытом виде
`README.md` и `config/account.json` предполагают хранение токена прямо в JSON. `Credential.token` (`config/data.rs:29`) — обычная строка.

**Действие:** приоритет переменным окружения (`API_TOKEN` уже поддержан в `main.rs:74`), добавить поддержку `.env`/секрет-менеджера, убедиться что `account.json` в `.gitignore`, маскировать токен в логах.

## 🟢 Низкий приоритет (качество / DX)

### 14. Покрытие тестами неравномерное
138 тест-функций, но они сосредоточены в `error.rs`, детекторах и чистой логике. Не покрыты денежные места: расчёт количества (п. 1), исполнение ордера, применение риск-лимитов. Есть `broker/mock.rs` — идеальная опора для интеграционных тестов пайплайна.

**Действие:** добавить тесты на `execute_via_broker`, sizing и риск-checks поверх `MockBroker`.

### 15. Смешение языков в кодовой базе
Комментарии/доки — местами русский, местами английский; `README.md` на русском, `AGENTS.md`/код — на английском. Логи тоже смешанные.

**Действие:** зафиксировать соглашение (напр. код/доки — EN, пользовательские доки — RU) в `CLAUDE.md`.

### 16. `println!`/захардкоженные баннеры вместо структурного лога
`main.rs:179-184` — ASCII-баннер через `log::info!`. Есть полноценный `logging` (console/file/network) и `telemetry`, но структурные поля (аккаунт, тикер) передаются форматированием строк, а не полями.

**Действие:** перейти на `tracing` со структурными полями — упростит парсинг логов и корреляцию с telemetry.

### 17. Магические числа в риск/ensemble-логике
`agent/multi_agent.rs` — пороги `0.3/0.6/0.2/0.15`, SL=`2.0 + risk*3`, TP=`SL*1.5`; `provider/prediction/mod.rs:107` — веса режимов вшиты. Их нельзя настроить без пересборки.

**Действие:** вынести в конфиг (или хотя бы в именованные константы с комментариями).

### 18. Grid-бот жёстко привязан к Tinkoff SDK
`strategy/grid_bot.rs` работает напрямую с `TInvestSdk`, а не через трейт `Broker`. Для Finam/Mock grid недоступен (`main.rs:359` явно пропускает аккаунт без SDK).

**Действие:** переписать `GridBot`/`GridExecutor` поверх `dyn Broker` — тогда grid заработает на всех брокерах и станет тестируемым на `MockBroker`.

## Быстрые победы (можно сделать за один заход)

1. Порог уверенности из конфига (п. 2) — 1 строка.
2. Удалить `trader-bot/Cargo.lock` (п. 11).
3. Заменить `Box::leak` на `Cow` (п. 8).
4. Убрать `run_standard_account`-обёртку (п. 7).
5. Снять крейтовые `#![allow(dead_code/unused_imports)]` и посмотреть реальный объём предупреждений (п. 5).

## Наибольший эффект (стоит спланировать отдельно)

1. Корректный sizing + hard risk-checks перед ордером (п. 1, 3) — прямое влияние на потери капитала.
2. Подключение ensemble/gates/supervisor к бинарнику или честная маркировка экспериментальными (п. 4).
3. Grid поверх трейта `Broker` (п. 18).
